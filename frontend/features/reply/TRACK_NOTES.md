# Reply — 楽曲/映像プロファイル

「Reply」(超かぐや姫 ライブシーン)の楽曲構成・ビートグリッド・実測ダイナミクス・映像の絵づくり。
`features/reply/` で音に合わせた3D演出・カメラ・照明・シェーダーのタイミングを決めるときに読む。

`frontend/public/videos/reply.mp4` は劇中歌「Reply」のライブシーン(超かぐや姫、かぐやが月に
帰る前のライブ)。**127.47秒 / 1920x1080 / h264**。`features/reply/` の演出はこの1本に同期する。

構成・歌詞のタイミングは**ユーザーが耳で取った値が正**。音響的な数値(BPM・帯域・音量・カット
密度)は reply.mp4 の音声から**実測**したもので、勘で置いた数字ではない。両者の出どころが違う
ことを意識して使い分けること(§2.4)。

機械可読版: [track-timeline.json](track-timeline.json)

## 1. ビートグリッド

| 項目 | 値 |
|---|---|
| BPM | **170.0**(実測 169.97 / 170.13 / 170.15 の3手法。170ちょうどとみなしてよい) |
| 1拍 | 0.352941 s |
| 1小節(4/4) | 1.411765 s |
| 最初の拍 | ≈ 0.022 s |
| 全長 | 約 90 小節 |

既存の [constants.ts](constants.ts) の
`REPLY_BPM = 170` / `REPLY_BEAT_OFFSET = 0.018` は**この実測と一致している**(拍位相の実測値は
0.0219s)。そのまま使ってよい。

### 1.1 小節頭(REPLY_BAR_ORIGIN)は音源から一意に決まらない — 重要

4拍のうちどれが小節頭かを、独立した3つの方法で求めたところ**答えが割れた**:

| 方法 | 出た小節頭 |
|---|---|
| キックのオンセット強度を4スロットに振り分け | 0.375 s |
| イントロの大アタック(§2.1)を1拍目とみなす | 0.39 s |
| キック/スネアを1小節に畳み込んでパターン照合 | 1.32 s |
| 既存 constants.ts の値 | 0.724 s |

決め手が出ない理由は畳み込みプロファイルを見れば分かる: **キックもスネアも1小節内でほぼ平坦**
(キック 0.43〜1.00、明確な4つ打ちもバックビートも出ない)。劇中のミックスで歓声・SE・台詞が
music に重なっており、ドラムが分離できていない。

→ **`REPLY_BAR_ORIGIN` は現状のまま変えないこと。** 音源に「正解」が無いので、動いている値を
触っても改善にならない。小節頭は*演出上の判断*として扱う。一方 BPM と拍位相は堅いので、
**拍単位の同期は信頼してよい**。

小節線をどうしても絵に合わせたいときは、下の実測アンカー(§2.1/§2.2)に合わせるのが唯一の
根拠のある寄せ方。

## 2. 実測アンカー(音が確実に動く瞬間)

小節頭と違い、以下は波形上で明確に立っているので**演出を当てる価値がある**。

### 2.1 イントロの2小節パルス
イントロ1の間、曲中で最も強いアタックが**ちょうど2小節(2.824s)間隔**で4回鳴る:

```
0.392s  3.219s  6.043s  8.867s     (間隔 2.827 / 2.824 / 2.824)
```

「てれれれんててん」の頭がここ。**曲全体で最大のオンセット**(強度1.00 / 0.88 / 0.85 / 0.71)
なので、組み上げアニメのブロック着弾・閃光・カメラのステップはここに当てると必ず合って見える。

### 2.2 ベース入り = 11.05s
低域(40-180Hz)が **0.05秒で +20dB** 跳ね上がり、低域比率が 0.5 → 4.6 になる。ユーザーの言う
「11秒からの転調した2回目のイントロ」の実体はこれ。ここから曲全体が +8dB 大きくなる
(イントロ1 -18.4dB → イントロ2 -10.2dB)。

`REPLY_BUILD_END_SECONDS = 11` はこの瞬間とほぼ一致しており、**天守が組み上がりきる=ベースが
入る**という設計になっている。11.05 まで詰めると更に合う。

### 2.3 フェードアウト = 121.3s 〜 127.37s
ユーザーの体感は「1:59(119s)から」だが、実測では **121.0s までレベルは平坦**で、実際に落ち
始めるのは 121.3s。完全な無音は **127.37s**(映像の終端 127.47s の 0.1 秒前)。

リニアゲイン実測値:

```
121.0→0.93  122.0→0.74  123.0→0.61  124.0→0.54
124.5→0.35  125.5→0.23  126.0→0.19  126.5→0.10  127.37→0
```

前半ゆるやか・**124.0〜125.5 で急降下**という形。等速フェードではないので、
`REPLY_OUTRO_FADE_SECONDS` の線形フェードを当てると音より先に絵が消える。上のカーブを
そのまま使うのが正確。

### 3.2 使い分け
歌詞の値は耳取りなので、拍グリッドに乗せると **±0.8秒** ばらつく(平均 ±0.45秒)。

- **構造・パルス**(明滅、ビーム切替、揺れ) → §1 のグリッドで駆動する
- **歌い出しのヒット**(キャラの動き出し、字幕、決めポーズ) → §3.1 の秒数を直接使う

グリッドに合わせようとして歌詞の値を丸めないこと。歌は小節頭より前から食って入る
(アウフタクト)ので、ずれているのが正しい。

## 4. 絵づくり(元映像の特徴)

### 4.1 パレット
- **地**: 夜の紺〜青緑。ほぼ全編この上に乗る
- **主アクセント**: マゼンタ/ピンク(鳥居、レーザー、彗星状の尾、桜の花びら)
- **副アクセント**: 暖色の金/橙(提灯、天守のライトアップ、爆発)
- **点描**: 緑の蛍(パーティクル)とサーチライトのビーム。緑は常に「動く光」として使われる
- **白飛び**: 転換で全画面が白く飛ぶカットが多用される(0:27-0:31、1:34 など)

既存の `BEAM_COLORS = ["#6effb0", "#ff4fa3", "#ffa93d", "#8b6cff"]` はこの配色と整合している。

### 4.2 モチーフ
鳥居(赤・並列)/ 提灯 / 五重塔・天守 / **巨大な満月を背にしたステージ** / 客席のサイリウム
(シアン・黄) / 桜の花びら / 緑の蛍 / 放射状サーチライト。
1:38 の「金色にライトアップされた塔＋月＋ピンクのオーロラ＋上空の光の粒」が構図の代表格で、
`features/reply/` の江戸城＋ステージ＋鳥居＋ホログラムの積み方はこれを踏襲している。

### 4.3 カットのリズム — **ビートには乗っていない**
ハードカット85個を検出して拍グリッドと照合したところ、拍から60ms以内に落ちるカットは
**28.2%(偶然の期待値34%)**。つまり編集は**意図的にビートに同期していない**。

代わりに効いているのは**密度**:

```
イントロ  0.25–0.36 カット/秒   (1カット 2.8–4.0秒)
Aメロ/Bメロ 0.48–0.59 カット/秒 (1カット 1.7–2.1秒)
サビ/後半  1.04–1.29 カット/秒  (1カット 0.8–1.0秒)  ← 約4倍
アウトロ  0.33 カット/秒
フェード  0(8.5秒の1カットで終わる)
```

→ **3D側でカット割りを拍に合わせて刻むのは元映像に反する。** 連続的な運動量(カメラ速度、
パーティクル量、露出)をセクションごとに4倍のレンジで動かすほうが原典に忠実。

## 5. 3D演出への落とし込み

1. **拍で駆動してよいもの**: ビームの色替え・明滅、リムライトの脈動、細かい揺れ。
   BPM 170 は1拍0.35秒とかなり速いので、全体を毎拍動かすとチカチカする。
   **2拍(0.71s)や1小節(1.41s)**を基本単位にし、拍は細かい要素だけに使う。
2. **セクションで段を作る**: 上の「明るさ」と「カット/秒」がそのまま演出強度のカーブになる。
   イントロ1(静・暗) → 11.05 でベース入り(段が1つ上がる) → サビ 62s で
   明るさ0.05→0.072・カット密度2倍(段がもう1つ上がる) → 121.3 から落とす。
3. **アンカーに当てる**: §2.1 の 0.392/3.219/6.043/8.867、§2.2 の 11.05、§2.3 の 121.3。
   この6点だけは外さない。
4. **エンベロープで駆動する**: [track-timeline.json](track-timeline.json) の `fade_curve`、および
   セクション別 `rms_db` / `brightness`。カット単位ではなく連続量で動かす(§4.3)。
5. **色**: 夜の紺を地に、ピンクと金を対で置き、緑は動く光にだけ使う(§4.1)。

## 6. 測定の再現手順と確度

```bash
ffmpeg -i frontend/public/videos/reply.mp4 -vn -ac 1 -ar 44100 -f f32le -
```
STFT(N=2048, hop=128) → 対数スペクトルのフラックスでオンセット包絡 → 局所中央値で適応正規化。
テンポは (a) 自己相関の櫛形フィルタ、(b) オンセット位相の円周コヒーレンス、(c) 8秒窓の
テンポグラムの3系統。カットは `ffmpeg -vf "select='gt(scene,0.5)'"`。

**確度**
- BPM 170、1拍0.3529s、拍位相0.02s … **高**(3手法一致、全窓で170.1、区間ごとのブレなし)
- §2 のアンカー3点 … **高**(波形上で単独のピーク/段差)
- セクション別の RMS・明るさ・カット密度 … **高**(単純な集計)
- **小節頭の位相** … **低**。§1.1 の通り決まらない。触らない
- 歌詞タイミング … ユーザーの耳取り。音響的に検証していない

**転写できていないもの**: Whisper API キーが未設定のため歌詞の自動転写は取れていない。
§3.1 はすべてユーザー提供。
